# 数据管线与数据纪律（设计稿）

> **性质**：方向性设计稿，**未实施、未排期**。排期归 [`../todos.md`](../todos.md)。
> 状态标注同 [training-design.md](training-design.md)：`已定` / `建议` / `未决`；外部数字只作**量级参照**。
>
> **一句话**：管线的正确性是**顺序问题**——伪影修复 → 抗混叠重采样 → **解析求值**；
> 任何"先取稀疏点再滤波"的写法都不可救，因为混叠在那一步已经发生。

---

## 1. 数据源与时间基准

| 源 | 已定（本期） | 主要风险 |
| --- | --- | --- |
| **自有动捕** | 采集 30–120（可到 240）fps，工程归一化后入库 | 掉帧、时间戳抖动、骨架标定漂移 |
| **外部动作素材**（MMD 等） | 大量、含更高频内容 | 见 §6.2：面元伪影、足滑、骨架语义、许可 |

### 1.1 时间基准的硬规则（`建议`，全部可自动化检查）

| 规则 | 原因 |
| --- | --- |
| **`Δt` 一律从真实时间戳计算**，不用"帧号 × 标称帧率" | 掉帧、可变播放速度、重复关键帧都会让名义帧率说谎 |
| 时间戳必须**严格单调**；允许有上界间隔（检出空洞） | 空洞若被插值吞掉会变成"平白多出的动作" |
| 检出并记录**重复帧 / 长时间静止** | 静止段会污染"最小有效幅度"类统计（参考实现有此参数） |
| 每个源记录**采集条件元数据**（设备、人物、场次、日期） | 划分与"泛化声明"都要用它（§7） |
| 每条资产记录**内容哈希 + 帧数**，入库时校验 `帧数 × 每帧字节` 恒等式 | 参考实现的 `tools/check.mjs` 用 `frames*53*16` 做形状自检，这条纪律应保留 |

## 2. 目标形态（D2，`已定`）

```
源（30–240 fps，不等间隔、可能有伪影）
   │  ① 在原生最密网格上修复伪影
   │  ② 抗混叠重采样 → 固定间距网格
   │  ③ 拟合为解析表示（样条 / 旋转空间）
   ▼
任意 t 的精确求值  ──►  任意 Δt 的训练样本（秒域，见 training-design §2.2）
```

要点：

- **固定间距网格**（`已定`）是给批次化用的**内部**表示，不是唯一真值——保留 ③ 的解析表示，`Δt` 的求值走它。
- **推理侧不重跑这条管线**。管线只负责产训练数据；推理侧的插值核必须与训练监督用的核**同族**（§8）。

## 3. 预处理顺序（`建议`——这是本文件最重要的一张表）

| 步骤 | 操作 | 判据 | 反例（会被它救回） |
| --- | --- | --- | --- |
| ① | 在**最密原生网格**上修伪影：丢帧补齐、重复帧去除、上采样台阶抹平、逐帧抖动抑制 | **谱熵**判据（§4），不用频率阈值 | 直接对稀疏点滤波 ⇒ 混叠已发生 |
| ② | 降采样时**先抗混叠**再取点（sinc/窗函数 sinc，或高质量样条重采样） | 降采样后逐链频带能量不得在 Nyquist 附近出现折叠峰 | 先取每 N 帧再低通 ⇒ 假频率被保留 |
| ③ | 拟合**解析表示**（外部素材的贝塞尔样条可原样保留；动捕转旋转空间样条/Squad） | 拟合残差与抖动统计 | 在网格上做线性插值取 `t+Δt` ⇒ 分数帧误差 |
| ④ | 只对**伪影频段**做带阻，**不对目标信号做全局低通** | 见 [training-design.md](training-design.md) §8 反模式 2 | 4 Hz 低通作用在脚/踝 ⇒ 冲击被抹成圆包 |

---

## 4. 伪影修复的判据：谱熵，不是频率阈值

"快动作频率更高"只对一半：**快动作是低熵、相位集中的宽带能量；抖动是高熵、相位随机的扁平谱。**
两者频率分布可重叠，熵差别很大。

参考实现的判据（`motion/multiscale_motion.mjs:11-12`）：

```js
const threshold = /hips|spine|chest|Leg|Foot|Toes/.test(name) ? 4
                : /head|neck/.test(name) ? 6 : 7.5;          // ① 分链阈值
// noise() 的四项：
small      = max(0, 1 - short.amplitude / .08)               // ② 幅度小
random     = max(0, (short.entropy - .65) / .35)             // ③ 谱熵高 ⇒ 像噪声
persistent = min(1, long.ratio / .2)                         // ④ 持续存在
noise      = min(.9, small * random * short.ratio * persistent)
```

`spectrum()` 本身（`motion/multiscale_motion.mjs:1`）做的是**去均值去趋势后的 DCT/余弦变换**，
输出 `power / high / entropy / amplitude / ratio`。

**建议做法**：逐关节、逐片段算这套量，**分别**决定哪些高频是刚体链条/上采样烘进去的抖动（砍），
哪些是真实快速摆动（留）。四个因子缺一不可——只判熵会把"快速的真实动作"误杀，只判幅度会把"小幅真实动作"误杀。

> 阈值 `4 / 6 / 7.5 Hz` 出自参考实现在**站立聊天**场景下的判定，**只作量级参照**，必须在我方素材上重测。

## 5. 逐链截止频率（D13，`建议`）

不要全局设一个截止频率，也不要"外部素材统一乘以 2"。依据应是**该关节的速度/加速度/jerk 上限**——
jerk 有限就意味着高频内容有理论上界。

参考实现的关节表（`motion/joint_feasibility.mjs:4` 起）给出了范式与量级：

| 链 | 速度上限 | 加速度上限 | 备注 |
| --- | --- | --- | --- |
| `hips` / `spine` / `chest` | 180°/s | 1 600–2 000°/s² | 最低频，躯干 |
| `LowerLeg` | 520°/s | 7 000°/s² | 硬范围 `[-155, 5]°`，软范围 `[-150, 3]°`；**扭转范围随屈曲角动态收紧** |
| `UpperArm` | 900°/s | 18 000°/s² | 高频 |
| `LowerArm` | 1 000°/s | 22 000°/s² | 最高 |
| `Hand` | 700°/s | 12 000°/s² | 高 |
| 指骨 | 650°/s | 10 000°/s²（jerk 160 000°/s³） | **最高**，且最容易被低通顺手砍掉 |

**方法**：把上表当作**初始猜测**，在我方骨架与素材上用 §4 的谱熵统计**实测**每链的有效带宽，
再据此设定该链的滤波截止与监督率下限（Nyquist = 2× 带宽）。躯干 4 Hz 的经验**不可外推到手指**。

## 6. 质量门限与划分纪律

### 6.1 门限（`建议`）——照抄参考实现的"先审后训"形状

| 件 | 参考实现在哪 | 建议保留的形状 |
| --- | --- | --- |
| 剔除记录 | `models/body/source-filter.json` | 逐段记录**决策 / 理由 / 对应条目 / 内容哈希**，可追溯 |
| 审核先于训练 | `models/body/review.json` 的 `trained_after_review: true` | 入库流程强制"审核发生在训练之前" |
| 质量评分 | `training/source_quality.mjs` | 按速度 / 高度 / 倾斜 / 奖励打分，低分不入库 |
| 数值校验 | `tools/check.mjs`、`web/v13_assets.mjs` | 形状恒等式 + 内容哈希 + 有限性检查 |

### 6.2 外部动作素材（MMD 等）的专属陷阱

| 陷阱 | 处理 |
| --- | --- |
| **"更多高频"不自动是好事** | 先按 §4 量一遍：手作/物理演算的次级抖动、上采样台阶、贝塞尔过冲、裙摆/头发的刚体链条，都是要被判为噪声的；真实冲击才保留 |
| **"真值"本身已是插值结果** | MMD 是逐参数独立贝塞尔采样 ⇒ **关节间相关性在源头就被破坏**。入库前测跨关节相位关系，与自有动捕对比；差异大则按来源条件化，或用动捕做末段微调 |
| **足ＩＫ必须烘成 FK** | 腿部动作是 IK 驱动的，FK 链可能与 IK 结果不一致；漏掉"足回転無効"类标志会让脚踝姿态错 |
| **腕捩/手捩（twist）骨要合并** | 否则扭转变换丢失或超范围 |
| **指骨/眼球缺失** | 显式 fallback 到底座先验，**不要填零**（参考实现自述 `"缺少指骨真值的技能保留底座手指"`） |
| **频谱不一致** | 高频源在高频段有真信号、低频源在同频段只有噪声；不按源归一化会让模型学到"高频时有时无" |
| **许可** | 外部动作/模型通常由作者逐件规定，多数**不允许随项目分发**；入库前确定边界（见 [README](README.md) §7 U5） |

### 6.3 划分纪律（`建议`，硬性）

| 纪律 | 原因 |
| --- | --- |
| **按来源 / 场次 / 片段划分**，绝不按帧随机划分 | 相邻帧跨集会虚高指标 |
| 每条资产带 `source.kind`（采集 / 参考 / 视频 / 生成）与采集条件 | 划分与泛化声明都要用 |
| 文档里写明**该划分能证明什么、不能证明什么** | 参考实现做对了"按文件划分"，仍自述 `"两个完整文件留出, 同人物采集条件, 非独立场次泛化"`——这是诚实的模板 |
| 训练/验证规模按**秒级**如实记录 | 参考实现的 v15 expert 是"推进 6 秒训练 / 3 秒留出"——记录它，避免后人误读为大规模训练 |

## 7. 离线核 vs 运行时核的一致性（`建议`，易漏）

训练监督用的插值核（离线，可用零相位）与推理时填充关键帧用的核（运行时，必须因果），
若**不同族**，训练目标与部署输出之间就有**系统性相位差**——不是噪声而是稳定偏差，模型会认真学到它。

| 选项 | 代价 |
| --- | --- |
| 两端用同一族（运行时也用零相位近似，接受半窗延迟） | 引入可感知延迟 |
| 两端都不做相位性滤波 | 需要保证源数据本身已无伪影（依赖 §3 步骤 ①） |
| 运行时用因果滤波、离线也**刻意使用同一因果核**生成训练目标 | 最稳，但训练目标会带该核的延迟（这是可接受的，因为部署也一样） |

**无论选哪种，必须显式记录**，并纳入验收（比较不同选项下的相位差指标）。

## 8. 复核命令

```bash
# 时间戳单调性与间隔分布（空洞/重复帧检出）
node -e 'const r=require("fs").readFileSync(process.argv[1]);' "$RAW"

# 逐链频带能量与谱熵（需要我方实现 spectrum()/noise() 的同型工具）
#   期望输出：每链的 power / high-ratio / entropy / amplitude

# 跨关节相位关系（自有动捕 vs 外部素材）
#   期望输出：同动作类别下配对关节的相位差分布

# Δt 求值残差：解析求值 vs 网格线性插值（用于证明 D6 的收益）
#   期望输出：残差随 Δt 小数部分的变化曲线；解析路径应平坦

# 资产形状自检（入库闸门）
node -e 'const s=JSON.parse(require("fs").readFileSync(process.argv[1],"utf8"));
const b=require("fs").readFileSync(process.argv[2]);
if(b.length!==s.frames*s.bones*16)throw Error("轨迹数据形状无效.");' meta.json clip.bin
```

> 参考实现里与我方复核直接对应的三处：`tools/check.mjs`（形状 + 哈希）、
> `motion/multiscale_motion.mjs`（频带/熵）、`models/body/source-filter.json`（剔除可追溯）。
