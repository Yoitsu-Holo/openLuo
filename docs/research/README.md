# 外部实现调研（research）

> **状态**：调研存档，**非规范**。本目录不定义 openLuo 的行为，也不承诺实施。
> **一句话**：把"外部项目怎么做某件事"的**证据与理由**存下来——避免重复调研，也避免把别人的实现当成我们的契约。

---

## 1. 边界（三条纪律）

| # | 纪律 | 理由 |
| --- | --- | --- |
| 1 | 本目录只存**证据与理由**，不存待办、不报实施状态 | 待办只有一份真值（[../todos.md](../todos.md)），实施状态只以 `../architecture/` 与代码为准；本目录若也列这些，会立刻产生两处漂移 |
| 2 | 每条结论必须带**来源快照**（仓库 + 提交号）与 `路径:行` | 外部项目会变；没有快照的引用无法复核 |
| 3 | 结论必须区分「可直接借鉴 / 需改造 / 不适用」 | 语义前提不同的照搬是本项目最容易犯的错 |
| 4 | 每份对比必须**先声明适用性前提差异** | 对方的整体方案往往成立在"一个工作区一份统一上下文"这类前提上；我方是**容器化 + 每回合动态构建**（可有局部持久化），可见性还是**方向性**的（私聊不泄漏到群聊）⇒ 前提不同则整套结构不可搬，只能借纪律 |
| 5 | 结论要标注**当前优先级**（近期 / 暂缓） | 主题可能"确实要做，但不在当前设计阶段"；不标注会让读者把取材库当成排期 |

## 3. 采纳路径（怎么把结论变成 openLuo 的一部分）

1. **挑一条**：从主报告里选一个编号（如 `A`），先确认它对应的问题在 [../todos.md](../todos.md) 里是**已有条目**（例如 A/D 对应 **D5**）还是需要新登记。
2. **定案**：若涉及模型级改动，先过 `todos.md` §3 的待裁决（需要人拍板）。
3. **落设计稿**：写进 `../architecture/` 对应文档（上下文预算与块序 → [context-budget.md](../architecture/context-budget.md)；域与可见性 → [context-domains.md](../architecture/context-domains.md)；外置/压缩若成体系则新建文档并在此登记指针）。
4. **实施 + 验证**：按登记表的"关闭判据"验证（单测 / E2E / 真机冒烟三者取适用者），完成后**删登记行**并写进提交信息。
5. **本目录不回填实施状态**。若某条结论后来被推翻，就在对应条目上就地加一行：`> 已推翻（YYYY-MM-DD：理由 + 依据）`。
